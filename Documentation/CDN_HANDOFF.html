2. Đã xong từng phase

Editor pipeline (Phase 0–1)

CdnBuildPipeline giữ chuỗi gate ở một chỗ duy nhất, dùng chung bởi CLI và tab Build: compile → state file có → version khớp → restriction → build → manifest → verify. Mọi gate chạy trước build, vì lỗi mà gate version chặn không phát hiện được sau đó. Kèm CatalogVerifier, BuildManifest + ContentDiff, CdnProfileManager, LocalContentServer, 2 workflow CI + 7 script.

Runtime (Phase 2–4)

CdnManager là điểm vào: InitializeAsync, CheckForUpdateAsync, ApplyUpdateAsync, GetDownloadSizeAsync, DownloadAsync, SetEnvironment, PromoteFailover, Cache. Dưới nó: CatalogService, DownloadService (retry + backoff + jitter, huỷ, pre-flight, CRC auto-repair), CacheService (dọn bundle cũ tự động sau update), CdnErrorMapper (phân loại theo mã HTTP), ICdnTelemetry.

Đóng góp lớn nhất của Phase 4

CleanObsoleteAsync chạy tự động trong ApplyUpdateAsync. Addressables không tự xoá bundle bị thay thế; sau hai mươi bản update người chơi mang theo hai mươi thế hệ content. Đó là câu trả lời thường gặp cho "sao game 8 GB".

5. Kiểu lỗi lặp lại

Không phải code sai. Là code chạy sạch, tự kiểm tra xanh, và không kiểm cái nó tưởng đang kiểm.

  • CatalogService phân loại lỗi bằng hàm nội bộ viết ở Phase 2 kèm ghi chú "Phase 3 sẽ thay" — Phase 3 thêm mapper và không quay lại. 503 ra Unknown + non-retryable, nghĩa là retry chưa bao giờ chạy cho thao tác catalog. Chỉ fault injection bắt được.
  • CdnBuildSnapshotTests — 4 test tên nghe như đo bundling thật, thực ra dựng bundle giả trong temp.
  • TotalChangedBytes đo hiệu kích thước thay vì số byte phải tải.
  • Phép đo tốc độ cũ không có đơn vị: phân số/giây nhân 100 gắn nhãn KB/s.
  • Corpus bản đầu: self-check đếm qua dict khoá ghép nên che mất việc entry bị dời group.
  • ArchiveAfterBuild, ResolvePath — viết xong, chưa ai gọi, bug nằm im.
  • core.autocrlf đổi LF→CRLF khi checkout, làm bundle khác hash dù không có gì thay đổi. Đã vá bằng .gitattributes.
Bắt buộc sau mọi lệnh Unity 
grep -c "error CS" build.log     # phải là 0
git status --short               # tác dụng phụ có xảy ra không
ls / sha256sum <file mong đợi>   # nó có thật không

Unity exit 0 kể cả khi assembly không compile và method không hề chạy. Và LogAssert.ignoreFailingMessages đặt trong [SetUp] không có tác dụng — runner reset nó sau SetUp.
